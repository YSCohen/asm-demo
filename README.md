# asm-demo: step-through assembly slides from a real CPU trace

⚠️ Generated by Claude ⚠️

`trace.py` assembles an AT&T-syntax snippet with GNU `as`, runs it one
instruction at a time in the Unicorn emulator, and writes every intermediate
register/memory state to JSON. `asmdemo.typ` turns that JSON into a single
Touying slide with one subslide per instruction.

This project requires `as`, `objcopy`, `make`, `typst` & `uv` (which handles the Python
dependencies). You can probably install them with the following, or something
similar:

```sh
sudo apt install binutils make
cargo binstall typst-cli
curl -LsSf https://astral.sh/uv/install.sh | sh
```

Run `make` to build `build/slides.pdf` from the `examples/` demos.

## Writing a new demo

Copy one of `examples/*.toml`:

| key            | meaning |
|----------------|---------|
| `c`            | C source to show (optional) |
| `asm`          | AT&T assembly, to be shown as written minus comments and `.directive` lines. A trailing `# c:N` links the instruction to line N of the C code so both get highlighted. |
| `panels`       | Left-to-right layout: any of `"c"`, `"asm"`, `"regs"`, `"mem"`, `"state"` (registers stacked on memory) |
| `regs`         | Initial register values. Registers not given show `?` until written. |
| `regs_shown`   | Registers to display; add `:hex` for hex formatting |
| `[[mem]]`      | Memory cells to display: `addr`, `size` (bytes), optional `value`, `label`, `hex = true`, `signed = false` (read the value as unsigned; default is signed) |
| `mem_title`    | Heading of the memory panel |
| `pointers`     | Registers (e.g. `"rsp"`) drawn as tags next to the memory cell they point at. Setting this switches the memory panel to the boxed layout (also used when `panels` is `"mem"` plus one other) |
| `[steps.N]`    | Optional `title` / `note` for step N (1 = first instruction executed) |
| `show_initial` | Add a step 0 that shows the starting state before anything runs |
| `show`         | Only make subslides for these step numbers, e.g. `show = [3, 4]` |
| `code_base`    | Address the code is loaded at (default `0x1000000`), e.g. `0x401080`. `rip` can be listed in `regs_shown` |

Note: in the boxed memory layout, a cell's border turns yellow once it holds a
value. A cell labelled `"unused"` is only highlighted on steps that change it.

Then add it to `slides.typ`:

```typst
#trace-demo(slide, json("build/mydemo.json")) // see configuration options
```

Options: `dim: true` greys out instructions not yet executed, `widths:` sets
the panel column widths, `addrs: true` shows each instruction's address, and
`code-size:` sets the code font size (default `0.7em`).

How the trace is built:
- Each slide shows the state *after* the highlighted instruction runs. Values
  that changed in that step are drawn in yellow.
- `call` to a label defined in `asm` is followed into the callee, and its
  `ret` returns for real. Any other `call` (e.g. `printf`) is stepped over, so
  the callee does nothing. Tracing stops at the outermost function's `ret`.
- Jumps and loops work: each step is a real execution, so a loop body shows up
  once per iteration. There's a 500-step limit.
- Memory at addresses `0x0`–`0x200000` is mapped.
